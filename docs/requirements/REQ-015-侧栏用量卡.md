# REQ-015：侧栏用量卡（token 计量 · 调用数 · 费用估算）

- 状态：已验证（TEST-015 全部通过）
- 关联：DESIGN-015 · TEST-015 · FEATURE-MATRIX 行 `Agent 核心/dsh-token-meter`
- 日期：2026-10-30
- 证据：活体核对 `docs/evidence/LIVE-UI-2026-10-30.md` §4——侧栏底部用量卡：
  "Today / **13.6M tokens / 21 calls / DeepSeek ¥4.73** / Updated 06:56 AM" +
  折叠按钮；点击进使用统计设置。

## 1. 背景

mygo 完全不计 token：用户对花销无感知（DeepSeek 按量计费）。DSH 用 token-meter
从 API 响应捕获用量并在侧栏展示当日汇总。本 REQ 复刻该卡：捕获 → 按天累计 →
侧栏展示（tokens/calls/费用估算），点击进使用统计。

## 2. 用户故事

作为用户，我在侧栏随时看到今天用了多少 token、调了多少次、大约花了多少钱，
并可折叠或点进统计页。

## 3. 功能需求（FR）

- **FR-1（捕获）**：llm 客户端解析每次调用的 usage（prompt/completion/total）——
  流式从尾块 `usage` 字段（请求带 `stream_options.include_usage`），非流式从响应体；
  经 `OnUsage` 回调上报（每次 API 调用一次，子代理调用同样计入）。
- **FR-2（累计与持久化）**：按本地日期累计到 `<数据目录>/usage.json`
  （`{"days":{"2026-10-30":{"calls","prompt_tokens","completion_tokens"}}}`），
  跨日自动分桶；启动加载历史。
- **FR-3（侧栏卡片）**：底部区新增用量卡（对齐原版布局）：Today 行（点击折叠/展开）、
  `N tokens · N calls` 行与 `DeepSeek ¥x.xx · Updated HH:MM` 行（点击打开设置·使用
  统计）；tokens 人性化格式（13.6M / 1.2K）；折叠状态持久化。
- **FR-4（费用估算）**：估算 = (prompt×价入 + completion×价出)/1M，价格常量按
  deepseek-chat 公开牌价假设（¥2/M 入、¥8/M 出），标注「估算」语义。

## 4. 非功能需求

- **NFR-1** usage.json 每次调用后落盘（小文件）；统计器并发安全（回调来自 agent
  goroutine，经 onMain 回主线程）。
- **NFR-2** 纯标准库。

## 5. 验收标准

- AC-1：流式调用捕获尾块 usage（OnUsage 一次回调，数值正确），请求带
  include_usage；非流式 Complete 同样上报。
- AC-2：recordUsage 两次 → 当日 calls=2、tokens 累加、usage.json 落盘；昨日数据
  不混入今日。
- AC-3：侧栏卡片显示 Today/tokens/calls/费用/Updated；点击统计行打开设置·使用
  统计（无头走主区回退）；Today 行折叠/展开且状态落盘。
- AC-4：`go test ./...` 全绿无回归。

## 6. 范围外

- 按模型分别计价（reasoner 牌价不同）与缓存命中计价；usage.json 的历史图表
  （设置·使用统计现有会话/事件计数不动）；跨设备同步。

## 7. 决策记录

- 价格为常量假设并标注「估算」：DeepSeek 牌价会变，硬编码事实优于假装精确；
  单一价格对（deepseek-chat），不按模型区分。
- 卡片放侧栏底部区（本地模式行上方），与原版位置一致；折叠交互改为点 Today 行
  （原版为独立折叠钮，行为等价、实现更简单）。
