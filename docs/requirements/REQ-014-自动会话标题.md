# REQ-014：LLM 自动会话标题

- 状态：已验证（TEST-014 全部通过）
- 关联：DESIGN-014 · TEST-014 · FEATURE-MATRIX 行 `会话与存储/dsh-session-title`
- 日期：2026-10-30
- 证据：`.dsh-ref/dsh-package.json` 含 `dsh-session-title` 与策略包
  `session-title-first-prompt-llm` / `session-title-all-prompts-llm` /
  `session-title-llm`；活体证据实验插件 "Conversation-following titles"。

## 1. 背景

新会话标题目前是首行截断（`ellipsis(text, 24)`），信息量低。原版用 LLM 从首条
消息生成标题（first-prompt-llm 策略随发行版交付）。

## 2. 用户故事

作为用户，我发出第一条消息后，侧栏的会话名自动变成一句有信息量的标题
（如「登录功能实现」），无需手动改名。

## 3. 功能需求（FR）

- **FR-1（触发）**：新会话（标题仍为「新会话」）发出第一条消息时，后台用当前生效
  模型生成标题；后续消息不再重命名（first-prompt 策略）。
- **FR-2（生成）**：非流式补全（llm.Complete，max_tokens 24，system 指令限制
  ≤12 字、无引号句号前缀）；输出清洗（去引号/空白/截断 24 rune）；空结果放弃。
- **FR-3（回退）**：任何错误静默保留 ellipsis 兜底标题；标题立即先以兜底显示，
  生成完成后覆盖并持久化 meta.json、刷新侧栏。
- **FR-4（安全）**：标题请求不带工具与会话历史；API Key 未配置时跳过。

## 4. 非功能需求

- **NFR-1** 异步执行（goroutine + onMain），不阻塞发送；失败无感。

## 5. 验收标准

- AC-1：Complete 对 mock 非流式端点返回内容；401 报错；请求不带 stream。
- AC-2：首条消息 → 标题异步变为 LLM 标题并落盘 meta.json；第二条消息不重命名。

## 6. 范围外

- Conversation-following titles（随每条消息刷新，原版实验插件）→ 后续实验开关；
  all-prompts 策略；用户手动改名优先级（无改名 UI）。

## 7. 决策记录

- 只做 first-prompt-llm（随发行版交付的策略），实验性的跟随式刷新不做。
- 标题请求不带历史：省 token 且避免把内容二次发给模型的风险。
