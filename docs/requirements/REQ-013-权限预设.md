# REQ-013：权限预设（composer 访问模式）

- 状态：已验证（TEST-013 全部通过）
- 关联：DESIGN-013 · TEST-013 · FEATURE-MATRIX 行 `Agent 核心/dsh-permission-presets`
- 日期：2026-10-30
- 证据：活体核对 `docs/evidence/LIVE-UI-2026-10-30.md` §4——composer 控件
  **"Access mode, current: Workspace Write"**；`.dsh-ref/dsh-package.json` 含
  `dsh-permission-presets` / `client-ui-permission-presets`。

## 1. 背景

mygo 的工具权限是二元开关（全局 auto_approve 或逐工具「总是允许」）；原版在
composer 提供权限预设一键切换。本 REQ 把审批行为升级为三档预设。

## 2. 用户故事

作为用户，我让模型跑不熟悉的仓库时切「只读」让它只看不动；日常用「工作区写入」
逐次审批；信任的重复任务切「完全信任」免打扰——一键切换、随时可回。

## 3. 功能需求（FR）

- **FR-1（三档预设）**：只读（变更类工具一律拒绝，不弹审批）/ 工作区写入（默认，
  逐次审批，含「总是允许」记忆）/ 完全信任（自动批准变更类工具）。
- **FR-2（composer 控件）**：操作行盾牌图标 + 当前模式名，Popover 三选一（当前项
  ● 标记 + 一句描述），切换即持久化并留 note。
- **FR-3（迁移）**：旧配置 `auto_approve: true` 加载时迁移为「完全信任」；设置
  ·工具权限的复选框与预设联动（勾选 = 完全信任，取消 = 工作区写入）。
- **FR-4（留痕）**：审批决策继续写轨迹（只读拒绝也留痕，decision=denied-readonly）；
  「总是允许」记忆不变。

## 4. 非功能需求

- **NFR-1** 纯本地逻辑，无新增依赖。

## 5. 验收标准

- AC-1：迁移——旧 `auto_approve:true` 配置加载后 accessMode()==完全信任；未知值
  归一化默认。
- AC-2：decideApproval 三档行为正确（只读不询问直接拒绝、完全信任不询问放行、
  工作区写入走询问流且 AllowAlways 记忆 + 轨迹留痕）。
- AC-3：composer 控件显示当前模式；Popover 三选一；切换持久化到 config.json。
- AC-4：`go test ./...` 全绿无回归。

## 6. 范围外

- 按 DSH 的沙箱语义把「工作区写入」限制为工作区路径内的写入（当前仅审批门语义，
  与原版沙箱包 dsh-sandbox 的差距已在台账单列）。

## 7. 决策记录

- 三档命名对齐活体证据的 "Workspace Write" 概念并以中文呈现；「完全信任」承接旧
  auto_approve 语义，避免两套开关并存。
