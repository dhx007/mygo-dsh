# REQ-010：会话内模型切换（composer 模型选择器 + /model 命令）

- 状态：已验证（TEST-010 全部通过）
- 关联：DESIGN-010 · TEST-010 · FEATURE-MATRIX 行 `界面/client-ui-model-selection`
- 日期：2026-10-30
- 证据：活体核对 `docs/evidence/LIVE-UI-2026-10-30.md` §4——composer 内
  **"Select model, current glm-5-3-flash"** 控件；DSH 启动日志
  "model listing from https://api.deepseek.com/models loaded 2 model(s)"（/models 拉取）。

## 1. 背景

mygo 的模型是全局配置（设置·模型），会话内无法切换；原版在 composer 有模型选择器
且模型清单来自 /models 端点。多模型场景（chat vs reasoner）需要按会话选择。

## 2. 用户故事

作为用户，我在输入框操作行点击当前模型名，弹出可用模型清单（来自 /models），
点选即把**本会话**切到该模型（全局默认不变）；也可以用 /model <名> 命令切换。

## 3. 功能需求（FR）

- **FR-1（会话级覆盖）**：会话可记住自己的模型（meta.model）；空 = 跟随全局默认；
  新建 agent 时用覆盖值，切换后下一条消息生效。
- **FR-2（模型清单）**：GET {baseURL}/models（OpenAI 兼容，Bearer 鉴权）拉取模型
  id 列表；失败回退内置清单（deepseek-chat / deepseek-reasoner）；清单含当前生效
  模型（即使不在远端清单里）；首次打开选择器时拉取并缓存。
- **FR-3（composer 选择器）**：操作行的模型名变为可点击控件（图标 + 名称 + 下箭头，
  对齐原版），Popover 弹出清单：每行显示模型 id，当前生效项标记；点选切换本会话；
  弹层注明「会话级切换，全局默认在设置·模型」。
- **FR-4（/model 命令）**：`/model <名>` 切换本会话（接受任意名称，便于自定义模型）；
  无参数显示用法与当前生效模型。
- **FR-5（持久化与生效）**：会话模型写入 meta.json；切换立即丢弃现有 agent（下一条
  消息用新模型重建）；全局默认仍在设置·模型，会话未覆盖时跟随全局。

## 4. 非功能需求

- **NFR-1** /models 拉取异步（goroutine + onMain），UI 不阻塞；失败静默回退内置清单。
- **NFR-2** 纯标准库。

## 5. 验收标准

- AC-1：ListModels 对 mock /models 端点返回排序后的 id 列表；HTTP 401 报错。
- AC-2：switchSessionModel 写 meta.json、丢 agent、新 agent 用新模型；清除覆盖后
  跟随全局。
- AC-3：/model <名> 生效；/model 无参数提示用法与当前模型。
- AC-4：composer 控件显示当前生效模型；Popover 列出选项并标记当前项；点选切换。
- AC-5：`go test ./...` 全绿无回归。

## 6. 范围外

- 设置·模型分区的全局默认改动（现状已可用）；按模型计价显示；reasoner 特殊渲染
  （思维链已有）。

## 7. 决策记录

- 会话级覆盖 + 全局默认两层：与原版"已保存的模型选择覆盖组合默认值"一致，且不打破
  多会话共享全局配置的现状。
- Popover 复用用户菜单模式（ui.Popover）：与既有交互一致，无新组件。
- /model 接受任意名称：兼容自定义/私有模型，不做白名单硬校验（清单仅作建议）。
