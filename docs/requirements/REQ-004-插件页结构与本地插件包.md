# REQ-004：插件页结构修订 + 本地插件包运行时

- 状态：已验证（TEST-004 全部通过；结构对齐以 2026-10-30 活体核对为基准）
- 关联：DESIGN-004 · TEST-004 · FEATURE-MATRIX 行 `插件体系/dsh-plugin-manager`、`dsh-config-editor`（等价承载）
- 日期：2026-10-30
- 证据：`docs/evidence/LIVE-UI-2026-10-30.md` §2/§5（活体核对：三段式结构、包模型、Add plugin、Shell 卡）

## 1. 背景

活体核对证实 REQ-002 的插件页结构假设不成立：DSH 真实结构为
**内置插件只读清单卡（可展开详情/配置）+ 实验插件开关段 + 已安装插件段（npm/git 包、
子插件树、Add plugin 入口）**，且安装/启停/配置的主入口在侧栏 Plugins 全局面板。
mygo 现插件页是「13 个工具开关的六分类分组」，需要结构修订；同时补上真正的
本地插件包（贡献自定义工具）——这是「一切皆插件」的实体化。

## 2. 用户故事

作为用户，我在插件页能像原版一样看到三段结构：内置插件清单（可搜索、可展开看详情）、
实验功能开关、以及我自己安装的插件包（每个包有版本/来源/子插件，可单独开关、可卸载、
可从本地目录或 git 仓库一键安装）；装一个包后，它的工具立即出现在标准模式的工具集里。

## 3. 功能需求（FR）

- **FR-1（内置插件清单）**：插件页与设置·内置插件分区改为清单卡：每行 = 名称 + 描述 +
  Enabled/Disabled 徽标 + 展开箭头；展开显示版本/来源/分类/挂载工具与启用开关；带搜索框
  过滤（两处各自记忆搜索词）；分类分组取消（分类作为详情字段保留）。
- **FR-2（实验插件段）**：新增「实验插件」段，第一项 = **持久终端**（Persistent terminals，
  描述对齐原版 "Keep shell processes alive across tool calls"）：开启后所有含 bash 的预设
  都挂持久 shell（不再限于极简）；状态持久化。
- **FR-3（插件包模型）**：包 = `<数据目录>/plugins/<id>/`，含 `plugin.json`
  （id/name/version/source/origin/description/tools[]）与工具脚本；每个工具是该包的
  **子插件**（可单独开关）；包级开关关闭 = 全部子插件关闭；包行显示 `n/m 子插件开启`
  与包状态（On / Partially on / Off）。
- **FR-4（工具运行时）**：包工具脚本为 JavaScript（`function run(args){…}`），在 goja
  沙箱执行（每次调用全新 VM），可用桥接函数 bash/read_file/write_file/glob/grep/
  web_fetch/web_search（与 PTC 同一桥）；单次执行超时 30s 强制中断；输出超 32KB 截断；
  `mutating` 工具走审批门。
- **FR-5（挂载与门控）**：启用中的包工具进入工具集（spec 来自 manifest：name/description/
  参数开放 object）；被停用（包级或子级）后从下一条消息消失；模型侧 `plugins` 工具的
  list 继续只列内置插件（包工具经自身描述可见）。
- **FR-6（安装）**：Add plugin 入口接受 **本地目录路径**（校验 manifest 后复制入
  plugins 目录）或 **git URL**（`git clone --depth 1`）；id 冲突报错；npm 来源仅作显示
  （registry 安装不做，见范围外）。
- **FR-7（卸载）**：包详情内「卸载」两步确认后删除包目录，其工具即刻从后续消息消失。

## 4. 非功能需求

- **NFR-1** 包目录扫描结果缓存于 app 生命周期，安装/卸载/启动时刷新，不逐帧扫盘。
- **NFR-2** 脚本无 require/文件系统/网络直连能力，只有桥接函数；VM 不暴露 goja 全局。
- **NFR-3** git 不可用时安装报错并提示手动放置目录；clone 失败清理半成品目录。

## 5. 验收标准

- AC-1：清单卡渲染 + 搜索过滤 + 展开详情（含开关）——ui.Tester 断言。
- AC-2：持久终端开关开 → 标准预设 agent 挂 Shell；关 → 不挂；状态落盘。
- AC-3：本地目录安装成功（目录被复制）；manifest 非法/缺字段/ id 冲突报错。
- AC-4：`git clone` 安装成功（用本地仓库测试）；卸载后目录消失。
- AC-5：包工具经 agent 执行返回脚本结果；桥接函数可用（脚本里写文件成功）；mutating 走审批；
  停用包后 spec 消失；超时脚本被中断报错。
- AC-6：`go test ./...` 全绿无回归（含既有 13 插件注册表断言）。

## 6. 范围外

- npm registry 安装（需要 node/tar 依赖；source=npm 仅显示）→ 后续评估。
- MCP（REQ-005）、插件市场 Discover 标签与自定义 market index（REQ-006）。
- 包工具的 KV/审批例外、包依赖解析、脚本热重载（改包后需重启会话生效）。

## 7. 决策记录

- 工具脚本每次调用全新 VM：包工具幂等性无法保证，常驻 VM 会共享全局态；DSH 的 PTC 运行时
  每次程序也是独立执行，语义对齐。
- 内置插件的启用开关保留在展开详情里（原版开关在 Agent 预设编辑里）：mygo 无 per-preset
  编辑 UI，全局开关是现有行为的延续，不回退功能。
- 包工具 spec 参数用开放 object（manifest 不强制 JSON Schema）：降低包作者门槛，描述字段
  承担引导职责。
