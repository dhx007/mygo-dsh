# REQ-006：插件市场（自定义索引 · 浏览 · 一键安装）

- 状态：已验证（TEST-006 全部通过；P0 插件集群至此全部交付）
- 关联：DESIGN-006 · TEST-006 · FEATURE-MATRIX 行 `插件体系/dsh-plugin-market`
- 日期：2026-10-30
- 证据：活体核对 `docs/evidence/LIVE-UI-2026-10-30.md` §2.1/§4——实验插件
  **"Custom plugin markets"**："Adds a Discover tab to Plugins for browsing and
  installing bundles from plugin market indexes you add"；DSH 包模型 npm/git + semver。

## 1. 背景

REQ-004 已实现本地包安装（手动输入路径/git URL）；插件市场补上「发现」环节：
用户添加市场索引（JSON 清单，URL 或本地文件），浏览其中列出的插件包并一键安装。
这是 P0 插件集群的最后一项。

## 2. 用户故事

作为用户，我在实验插件里打开「自定义插件市场」，添加一个索引地址（社区维护的
JSON 清单），插件页市场段列出可用插件包，点「安装」即可装上并立即可用。

## 3. 功能需求（FR）

- **FR-1（实验开关门控）**：实验插件段新增第二项「自定义插件市场」（描述对齐原版）；
  开启后插件页出现「插件市场」段，关闭即隐藏；状态持久化。
- **FR-2（索引管理）**：索引地址存 `<数据目录>/markets.json`（`{"indexes":[...]}`，
  字符串数组，URL 或本地路径）；市场段可添加/删除（两步确认）索引。
- **FR-3（索引拉取）**：http(s) URL 用 GET（10s 超时）拉取；本地路径直接读取；
  解析 `{"name","plugins":[{id,name,version,description,source,origin}]}`；多索引合并
  按 id 去重（先到先得）；单索引失败不影响其他索引，全部失败报错。
- **FR-4（浏览）**：市场段列出条目（名称 + v版本 + source 徽标 + 描述 + origin）；
  已安装的包显示「已安装」标记且不可重复安装；手动「刷新」按钮触发异步拉取
  （UI 不阻塞）。
- **FR-5（安装）**：条目「安装」按 origin 分派——source=git 走 git clone，否则按本地
  路径导入（复用 REQ-004 的安装与校验）；成功后包出现在「已安装插件」段，工具从
  下一条消息可用。
- **FR-6（安全）**：安装仍走 REQ-004 全部校验（manifest 合法性、id 冲突）；市场内容
  是不可信输入——仅作展示，安装动作用户显式触发。

## 4. 非功能需求

- **NFR-1** 索引拉取异步执行（goroutine + onMain 回 UI 线程），失败信息可见于市场段。
- **NFR-2** 纯标准库（encoding/json + net/http）。

## 5. 验收标准

- AC-1：实验开关开 → 市场段出现；关 → 消失；状态落盘。
- AC-2：markets.json 读写；添加/两步删除索引持久化。
- AC-3：本地索引文件解析出条目；坏 JSON 报错；多索引合并去重。
- AC-4：UI 添加索引 → 刷新 → 条目可见；「安装」后包进入已安装段（用本地 git 仓库
  作为 origin，无需网络）。
- AC-5：`go test ./...` 全绿无回归。

## 6. 范围外

- DSH 的 Discover **标签页**形态：mygo 插件页是分区滚动布局，市场作为第五段呈现
  （已声明差异）；官方内置索引（需要官方源）；npm registry 条目；包更新检查
  （Plugin manager 标签职责）；索引签名/防篡改。

## 7. 决策记录

- 门控走实验开关（照搬原版 "Custom plugin markets" 的实验定位）而非注册表第 15 项：
  原版证据明确，且避免注册表膨胀。
- 索引格式自定义 JSON 而非 npm registry 协议：市场起步只需「名称+版本+来源」最小集，
  npm 协议留待真实需求。
- origin 按 entry.source 分派安装；source=local/npm 的远程 origin 无法安装（报错提示）。
